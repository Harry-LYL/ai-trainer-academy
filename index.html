01 · Pipeline

训练师整体链路 · 11 个环节

训练师是「模型导师 + 数据项目管家」：上游接 AI 产品经理（体验缺陷驱动）与算法工程师（模型能力驱动）的需求，把抽象需求翻译成可执行的数据生产标准，管理下游标注员产出「理想态数据」，交付后进入训练与评测，再用 Bad Case 反哺规则——形成闭环。点击任一环节查看详解。

🔁 数据飞轮闭环：交付不是终点。业务方验收后提出的 Bad Case → 训练师归因分析（数据问题 or 模型问题）→ 对齐双方规则 → 优化规则文档 → 下一批次更高质量投喂。小批量测试（3000 条）→ 效果评估 → 正向反馈后加大投喂（5000–10000 条）。

03 · Training Stages

模型训练三阶段 · 训练师在每一段做什么

「预训练造就模型的能力上限，后训练决定模型好不好用。」从通才到专才再到自我进化——行业内 60%–70% 的训练师项目集中在 SFT 阶段。

PT

① 预训练 Pre-training

「无监督学习」——投喂海量原始数据（网页/书籍/代码），让模型自己学预测下一个 Token。产出 Base Model：什么都懂，但不会对话、不懂指令。
  • 数据规模：千亿至万亿级 Token（Common Crawl / HuggingFace）
  • 主导方：算法工程师（选基座、调结构、设计清洗规则）
  • 训练师工作：辅助数据清洗，整理数据内容与数据类型
SFT

② 有监督微调 SFT

「教它说话」——提供高质量「问题 → 标准答案」对，让模型学会听从指令与对话格式，从通才蜕变为垂类专才（医疗/法律/代码）。
  • 项目占比：行业 60%–70% 的项目集中于此
  • 数据量级：几千～几万条（区别于评测的 100–300 条）
  • 训练师工作：撰写标注规则 → 构建高质量数据集 → 把控标注质量
  • 项目形态：单轮问答 / 多轮问答 / 各领域专项
RL

③ 强化学习 RLHF

「自我进化」——人类评估员给回答打分排序，奖励模型（RM）学习人类偏好，反向指导大模型迭代，输出最符合人类价值观的答案。
  • 数据来源：用多个模型（GPT-4 / o1 / 文心 / 豆包 / 通义）对同一问题生成不同回答
  • 核心环节：人工标注排序是 rewards 数据构造中最重要的环节
  • 训练师工作：训练奖励模型，实现大模型自主学习
  • 简化方案 DPO：直接偏好优化，1 个偏好回答 + N 个非偏好回答，跳过独立 RM

🏅 RM 奖励数据标注五步流程

① 两两比对N 个回答 pairwise 比较
→
② 生成排序由对比结果得出完整排序
→
③ 一致性校验暂定三人一致性
→
④ 取高一致率只采用高一致部分，有问题重标
→
⑤ 争议讨论难一致的 case 讨论优化标准细节

RLHF 的痛点：复杂且不稳定（先拟合 RM 再 RL 抽样更新，多阶段易震荡）、计算开销高（PPO 需大量采样）——这也是 DPO 出现的动机。

对比项CoT 提示工程SFT 监督微调RM 奖励模型
实现方式修改 Prompt（指令/少样本），不动模型参数在高质量「输入-输出」对上额外训练，调整权重用人类偏好数据训练一个独立评估模型
核心目的提升复杂推理能力，逐步思考定制特定任务/领域/风格学会评估输出好坏，为 RL 提供奖励信号
优点快速灵活、成本低、可解释效果显著、深度定制自动化评估质量、对齐人类价值观

三者结合CoT 输出可作 SFT 训练数据；SFT 可微调模型更好生成 CoT；RM 可评估 CoT 质量并通过 RLHF 优化。

06 · Guidelines

规则文档方法论 · 训练师的核心产出

规则文档（Guidelines）是下游唯一的执行准绳：把需求转化为「傻瓜式」执行规范，保证 32 个标注员不会出现 32 种动作。善用大模型辅助润色生成，但判定标准必须由训练师定义。

📄 文档标准结构

模块内容性质
背景所属模型、业务目标、训练阶段必备
标注概要总量、交付时间、人员配置必备
标注规则 + Case判断维度与依据：什么是好数据、什么是坏数据必备
标注方案劣质数据删除还是人工改写等实施策略必备
标注流程 / 排期 / 验收标准提升标注员理解效率辅助
Case 是文档的灵魂：正例 Good Case（正确范式）+ 负例 Bad Case（易错点与错因）+ 边界案例 Edge Case（模糊地带处理标准），三者缺一不可。

📐 评价维度：通用五维 + 专项加权

  • 安全性 Safety：回答有没有害？涉政违法、价值观、风险规避
  • 准确性 Accuracy：是不是事实？有没有幻觉？
  • 有帮助性 Helpfulness：是否正面解决用户问题（满足度）
  • 无害性 Harmlessness：有无歧视、偏见、冒犯
  • 格式 Format：排版、长度、结构、语言一致性
专项类型重点维度
医疗问答准确性、安全性权重极高 + 免责声明自然植入
创意写作流畅性、创造力、格式
代码生成可运行性、简洁性、注释质量
客服对话礼貌性、解决率、简洁度
多轮对话上下文连贯性、记忆一致性、意图识别

🔄 规则不是写完就不动的 · 四个迭代触发器

🐛 发现新问题
标注员反馈某类 case 没覆盖到
📊 数据分析
某维度分歧太大 = 定义不清
🔄 模型迭代
模型能力变了，规则跟着升级
🌍 市场变化
新地区要加当地文化/法律规则

试标过程中以及试标后拉齐规则，过程反哺规则文档；业务方验收后根据 Bad Case 对齐双方规则，持续优化。

07 · PM & QC

项目管理与质量把控

面试必考「排期规划」逻辑：项目总耗时 = 总数据量 ÷ (人效 × 人数)，且必须预留容错率（请假、规则突变）。下面是一个可交互的排期计算器。

质检追加天数
–

课堂示例：40000 条 ÷ (10 人 × 80 条/天) = 50 天基础排期；质检与容错另计。人效无固定标准——先自己跑 10–20 条得出体感（约 1–2 分钟/条），单轮 vs 多轮、复杂场景 vs 单一主体差异很大。

🛡️ 三层质量防线

① 标注员自检 / 互检主观数据「三人盲标，取最大共识」；每日在线复盘解决争议 case
② 质检员抽检 30%–40%医疗/法律等严谨领域 100% 全检；评测项目抽检常见 10%–15%
③ 训练师二次抽检训练师抽检质检员，保证质量不下滑；共性问题收集进备注文档 / bad case 库

👥 团队构成与准入

  • 内包/实习生：稳定好用，适合高质量垂直领域（如清北/博士实习生）
  • 供应商/外包：适合大规模、低难度任务
  • 众包：分散灵活，但质量波动大
  • 准入机制：试标准确率 ≥90% 才能进正式项目；评测岗试标通过线 80%，最多 3 次机会否则换人
来源：第一周笔记「项目全流程管理 / 排期公式 / 质检比例」+ 评测笔记「试标 / 正式评测 / 质检」+ AI竞品分析＆评测「人效标准」
08 · Evaluation

评测体系 · 给 AI 大脑做全面考试

核心区别：标注最终交付的是数据，评测最终交付的是评测报告。评测是 PM/训练师无法被 AI 替代的核心能力，大厂面试必考。数据量级 100–300 条（最多 400–500），切勿与 SFT 的几千几万条混淆。

📚 评测集构建三维度

  • 模型陌生的：必须是模型完全没见过的全新数据（高中生不能用小学题考试）
  • 多维度丰富的：不同题型混合（应用题/选择题/填空…）
  • 难度梯度：简单/中等/困难搭配

示例 K12 数学：学段（小/初/高）× 题型（算术/奥数/应用）× 难度。来源含网络拉取（优先近期时效数据）、第三方采购等（课件四大来源表）；按场景分类每类 ≥20 条。定期收集（日常顺手归档）+ 定期更换（防过时）；网络数据重复由算法校验后补充。

🎯 三种评测方法

  • 对比法 GSB：A 比 B 好(G)/一样(S)/差(B)；SBS 细化为 7 档。直观快速，但难量化、难定位问题
  • 评分法：5/4/3/2/1 五档或三档制，维度建议 4–6 个，每档必须配明确解释。可量化、可定位弱项，但人力成本高
  • 二值判断：通过/未通过。简单高效，但主观性强、无法定位

混合评测策略（GSB+评分 / 二值+评分）弥补定位能力；双盲多人评测同一批数据避免单人主观偏差。

🔺 置信度三角（面试重点）

  • 评测集构建：陌生 × 多维 × 难度梯度保证科学性
  • 方法选择：快速验证用对比法，精准定位用评分法，高置信要求用混合法
  • 标注方式：双盲 + 多人评测增加支撑度

评分统计三方式：各维度平均分 / 整体满意度 =（非常满意+满意）÷ 总量 / 问题占比 = 有问题数据 ÷ 总数。档位设计要「说得通」，避免冗余档位。

🧮 GSB 盈率计算器

盈率 = (G 数量 + S 数量 ÷ 2) ÷ 总样本数 —— S 平分一半给 G、一半给 B。

📑 评测报告五大模块

  • ① 评测信息：目的背景 / 模型版本号+发布日期（如 doubao-seed-0410）/ 有效与无效数据说明 / 人员
  • ② 评测标准：评分维度（约 5 个）/ 方法（如 GSB+评分混合）/ 评分卡详解
  • ③ 评测结果：分批数据 + 盈率 + 平均分，必须量化
  • ④ 核心结论：各模型优缺点 + 排序（如 B>C>A）——最体现能力
  • ⑤ 具体案例：经典 Bad Case + 算法校验回复（如「切块上下断点导致召回不全」），为优化提供依据

紧急交付用简化版：结论前置，保留结果+结论+经典 case。流程管理：试标 20–30 条 → 规则 1.0 → 培训试标（80% 通过线）→ 正式评测每人每天 100–600 条 → 交付预留约 5 天缓冲。

09 · Automation

自动化提效 · 做流水线的设计师，不是工人

自动化数据工作流 = 用脚本规则 + 高智商模型，接管采集、清洗、扩写、标注、质检、评测环节。人类不可替代的价值：主观审美、情绪感知、社会热点嗅觉，以及「洞察问题 → 制定提效方案 → 实施验证」的思路。

⚙️ RPA vs IAA

  • RPA 机器人流程自动化：规则匹配 If-Then，适合高度结构化任务（如提取 Excel 含「吃饭」关键词的行）
  • IAA 智能化流程自动化：AI/NLP + RPA，能意图识别与模糊匹配，不仅执行规则还能「理解」规则

🛠️ 三大提效工具（写进简历）

  • PE 提示词：重复性描述任务；结构化 Prompt 约束模型按格式输出
  • 工作流/智能体：Coze（低代码最简）/ Dify（B端常用）/ n8n（专业性强）；节点 = 变量接力，SP 全局规则权限高于 User PE
  • Python 脚本：十万级数据清洗/生成最高效；AI IDE（Cursor）写脚本调 API。API 三要素：URL + API Key + Model。真实案例：150 条数据分类人工 1 小时 → 脚本 2 分钟，团队提效 20–30%

⚠️ 组织合规红线：部分传统/军工企业禁用自动化工具，只能 Excel 手工处理。Skill 技能包 = Markdown 规则文档 + 渐进式按需调用，省 Token；可做「人性化改写」（不同 MBTI/情绪/长短句）避免数据同质化。

🔁 PE 生产闭环六步法

① 需求分析与拆解明确理想态：目标、输入格式、字段、业务边界
② 能力摸底判断模型能力边界能否胜任——方向错了调优徒劳
③ 编写初始 PE清晰明确、Markdown 结构化、上下文+示例、要求自查
④ 归因与验收小步快跑每次只调一个点；Bad Case 归因（语义误解/细节缺失/格式错误）
⑤ 循环测试调优多模型 A/B Test 防「偷懒」；连续 5 次以上稳定达标
⑥ 批量验收落地扩样本跑批 + 随机抽检；记录投产前后对比（8 分钟→5 分钟，质量 3.6→4.3）= 面试核心亮点

PE 真实工作状态：20% 构建初始框架，80% 微调迭代。图像优化 PE 推荐反向推导法：原图+原 Prompt+糟糕生成图全给模型 → 让它分析问题 → 自写新 Prompt → 验证出好图 → 反推通用 PE 框架。

⚖️ LLM as a Judge 自动化评测避坑

先原因后打分
模型基于下文预测，先分析再打分准确度远高于先打分后解释
警惕三大偏见
位置偏见（偏爱 A）/ 冗长偏见（偏爱字多）/ 自我偏好（偏爱自家输出）
人机分工
机器评重复、规律、标准性强的内容；人类负责审美、情绪、网感与高危合规判断
面试必杀技 · 迪士尼故事框架：背景（业务卡点多低效）→ 冲突（传统方法为何行不通）→ 思路（为何选 RPA/IAA/PE 方案）→ 成果（投产前后人效与准确率对比）。不要干巴巴罗列工具。

12 · Career

职业进阶与面试通关

「不要仅仅为了找一份工作而来，要为了改变职业轨迹而来。」你原本的专业背景不是废纸，而是最大的护城河——AI + 垂直行业（医疗/法律/建筑/金融）是最大风口。

📈 3-6-2 进阶战略

起
起步期 · 前 1.5 个月
高强度学习，掌握 AI 底层逻辑
累
积累期 · 3–6 个月
入职中小厂/外包，真实项目积累战斗经验
爆
爆发期 · 2 年+
深耕成长性初创公司，目标年薪 30 万+

薪资参考：0–3 年主打高性价比执行力（12–15k）；3–5 年主打垂类深度+带兵打仗（15–20k+，项目经理/AI 产品助理级）。学历只是门槛，专业度、笔记质量、社交圈层才拉开差距。

🚪 过五关斩六将

  • ① 简历被看见：100 分简历，匹配系统与 HR 搜索标签
  • ② 电话约面：确认意向与基本背景
  • ③ 业务一面：全流程跟进能力 + 工具熟练度
  • ④ PM/负责人二三面：复杂项目管理、专业深度、抗压
  • ⑤ HR 谈薪 Offer：薪资结构与到岗时间

去向两类：大厂（阿里/美团/字节）+ 垂类头部（新能源车企的车载 Agent 生态需求极大）。Boss 策略：关个性化推荐破信息房；关键词扩搜「行业+AI / 数据运营 / AI产品运营 / 多模态模型调优」；状态改「离职随时到岗」。

黄金 15 字打招呼：[年限] + [核心行业/业务] + [核心结果/能力]。例：「两年医疗大模型评测经验，熟悉 RAG 流…」✗ 错误示范：「您好，请问还招人吗？」

💎 简历稀缺标签

  • 懂业务全流程：需求对接→规则拆解→SOP→试标培训→质检验收
  • 懂提效自动化：AI 工具、PE、工作流提效（量化对比数据）
  • 跨团队协同：算法/产品/专职/外包复杂协作
  • 隐藏加分项：自媒体网感（多模态训练天赋证明）/ Python+SQL（降维打击）/ 外语（海外高薪项目）/ 硬核专业（垂类大模型直通）
面试杀手锏 · 个人知识库：X 轴 = 工作流横向（需求承接/试标/培训/标注/质检验收/交付复盘方法论）；Y 轴 = 技术纵向（RAG/Agent/多模态 Prompt）+ 行业纵向（医疗红线/金融政策/车企规则）。本页就是这份知识库的可视化形态。

⚠️ 面试复盘 · 致命坑清单（真实复盘笔记）

数据口径改口
简历写人效 80→120，现场改口「大概 30%」= 涉嫌造假。统一口径或改真实数字后死背
项目归属混淆
智驾/具身/漫剧/评测边界说不清。口诀：智驾=标注带团队，具身=Caption 提效 50%，AIGC 评测=12 份横评报告，漫剧=Agent 工作流压缩到 6 小时
术语发音
GSB 不是 GBS；双盲不是双王。开放题停留在「开会确认需求」会被直接终止
外行听不懂
优势解释堆术语被打断。准备「电梯演讲」版；口头禅用停顿代替；自我介绍背熟 30 秒版

讲项目黄金公式（竞品分析课）：痛点 → 手段 → 结果，并在背景里刻意埋「钩子」关键词引导追问。离职原因优先不可抗力 + 对学习的渴望，不吐槽前公司。
